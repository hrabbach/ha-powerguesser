# PowerGuesser 0.2.2

The first feature release since 0.2.1. Detection and learning are unchanged; what is new is that
Review now shows **evidence** for each candidate and device, so you can tell similar candidates
apart ("shower 1, shower 2 or a misidentification?") without waiting for the next learning run.
The three v1.0 cleanup gaps are also closed. There is no new requirement and no LLM behaviour
change.

## What's new

- **Review shows evidence per candidate.** Under a candidate (and under a confirmed device) you
  now see its recent runs, a rhythm line, a power and energy profile, and — when phase channels
  exist — the phase, with all run times in your Home Assistant time zone. The hints under it are
  explicitly labelled **heuristics, not accuracy**: they describe how much the data supports the
  candidate, they are not an accuracy or a confidence figure.
- **Existing candidates gain evidence on their own.** A few minutes after the update, a local
  background refresh computes evidence for candidates that were learned before this release. It
  runs **without a new LLM run**, sends nothing to your endpoint, and needs no action from you.
- **Confirmed devices show the same evidence.** A confirmed device's block is replayed locally
  from its active learned parameters, so it is directly comparable to the candidate it came from.

**Where to find it:** Review is the only place the evidence appears — open *Settings → Devices &
services → PowerGuesser → Configure → Review candidates*, then pick a candidate or a device. Its
block is shown under the item's name.

## Fixes and maintenance

- **The LLM endpoint probe result is now in diagnostics.** A diagnostics download includes the
  latest capability-probe result (strategy, token parameter, whether temperature was sent, the
  model the endpoint returned, any model mismatch, and when it was probed). The base URL and the
  API key are **redacted**.
- **The learning status sensor reports when the last attempt started and ended.** Three new
  attributes — `last_attempt_start`, `last_attempt_end` and `last_attempt_outcome` — show the last
  attempt's timestamps and how it ended, including for **failed**, **capped**, **stopped** and
  **interrupted** runs (an attempt reads **interrupted** when the previous process died while it was
  still running — an unclean restart; a graceful restart records it as **stopped**). `last_run`
  keeps its meaning of "the last *successful* run".
- **Review actions run through one shared backend** (confirm, rename, dismiss and merge, for both
  candidates and devices). This is a behaviour-preserving refactor with no change to what the
  buttons do.

## Install

Same as 0.2.0 — install or upgrade through the Home Assistant Marketplace ("Add from link" custom
repository, `https://github.com/hrabbach/ha-powerguesser`), then restart Home Assistant. This
build installs over 0.2.0 and 0.2.1; the upgrade needs no reconfiguration and touches no stored
device data.

## Known limitations

Unchanged from 0.2.1: this is a **0.x release** (the hardware UAT is still open, so 1.0.0 comes
later); **30 s meters are the design baseline**; step detection needs an **effective interval of
45 s or less**; **program devices cannot be merged** in v0.x; and some device classes legitimately
read **not validated** until enough plug holdout events exist.

Two limitations specific to this release's evidence:

- Evidence counts a candidate's **own runs only**. Two candidates that were merged are not pooled,
  so the merged candidate's evidence reflects the surviving signature's runs.
- A run's time of day can be off by **one hour on DST change days**.

## Accuracy

No accuracy figure is claimed here. The evidence block's hints are **heuristics, not accuracy** —
they summarise the data behind a candidate, not how well it detects. Accuracy remains the README
table, generated from the validation report; classes without a passing validation read "not
validated".
