# PowerGuesser 0.2.0

The first public release of PowerGuesser, a Home Assistant custom integration for non-intrusive
load monitoring (NILM): it learns per-device power fingerprints from the whole-house consumption
signal you already have in the Energy dashboard, then tracks the energy of consumers that cannot
be metered directly.

## What you need

- **Home Assistant 2026.11.0 or newer.**
- **Energy dashboard sources configured**, including at least the grid `stat_rate` power entity.
  Solar and battery sources are used when present.
- **An OpenAI-compatible LLM endpoint** (base URL, API key, model) for the learning phase. The
  endpoint is used only while learning; day-to-day detection runs locally with no cloud and no AI.
- **About three weeks of data** before validated candidates can be discovered.

## Install

PowerGuesser is installed as a custom repository in Home Assistant's built-in Marketplace (HACS
is part of HA since 2026.11):

1. Open **Settings → Devices & Services → Add Integration → Marketplace** and choose
   **"Add from link"** (custom repository).
2. Enter the repository URL:

   ```
   https://github.com/hrabbach/ha-powerguesser
   ```

3. Install **PowerGuesser** and restart Home Assistant.
4. Add the integration: **Settings → Devices & Services → Add Integration → PowerGuesser**.

## What is in 0.2.0

- **Gross home power and remainder** sensors derived from the Energy dashboard's `stat_rate`
  sources, with its own compact rolling buffer.
- **LLM-assisted learning and review**: candidate prototypes are discovered locally, named through
  your own LLM endpoint (with a consent step that shows the destination and the data sent), and
  offered for confirm, rename, merge or dismiss.
- **Confirmed switched devices** with virtual power and energy sensors, versioned updates with
  rollback, rename, retire and retrain.
- **Confirmed program appliances** (dishwasher, washing machine, dryer, hob sessions): if your
  appliance starts as a single ON/OFF device, you can train it with a plug temporarily moved onto
  it, and multi-state programs are recognized from the whole-house signal alone once learned.
- **Joint overlap attribution** when two confirmed devices switch together: each edge is explained
  against small device subsets, and an ambiguous edge is refused rather than guessed.
- **Temporary plug sessions**: assign a smart plug to a candidate or a confirmed device for a
  period; the plug's readings become labelled examples and validation ground truth, and labels stay
  correct after the plug moves on.
- **Holdout validation**: every claim is checked against held-out smart-plug measurements, and the
  validation report is the single source of the README's accuracy table. The release claims
  accuracy only for device classes that pass.

## Known limitations

- This is a **0.x release**: the hardware UAT is still open, so version 1.0.0 comes later.
- **30 s meters are the design baseline.** Faster meters unlock finer features when available.
- Step detection needs an **effective interval of 45 s or less**; coarser sampling disables it.
- **Program devices cannot be merged** in v0.x, neither as a merge source nor as a merge target.
- Some device classes legitimately read **not validated** until enough plug holdout events exist.
