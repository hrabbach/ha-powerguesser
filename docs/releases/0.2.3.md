# PowerGuesser 0.2.3

This release adds **guided capture**: you can teach PowerGuesser a device by capturing one real run,
and it appears immediately in Review as a local preview candidate. Detection and learning are
otherwise unchanged; a later learning run now **merges** with your capture for the same load instead
of creating a duplicate.

In this release the capture entry points are **admin services** (Developer Tools → Actions). The
dashboard entities, the capture screen in the options menu and the automation surfaces arrive in the
next release.

## What's new

- **Capture a past run (retroactive).** `powerguesser.capture_window` takes a start/end time and a
  device name; it snaps the window to the real rise and fall edges of the run in your whole-house
  residual, stores the capture locally, and shows a preview candidate in Review at once.
- **Capture a run live.** `powerguesser.capture_start` ("on now") and `powerguesser.capture_stop`
  record a run as it happens; `powerguesser.capture_cancel` discards an open capture. An abandoned
  live capture expires on its own and is swept clean after a restart.
- **Manage captures.** `powerguesser.capture_list` returns every stored capture (or one by id) with
  its result and interpreted window; `powerguesser.capture_delete` removes one;
  `powerguesser.capture_reassign` moves one to a different target.
- **A quality verdict, with a stated reason.** Every capture is judged clean, contaminated, ambiguous
  or none, and every refusal (a window across a sampling gap, a name already in use, an unknown
  target, a run with no clear edges) says which check failed. Windows are read in your Home Assistant
  time zone and handled correctly across DST.
- **Capture-aware Review.** A candidate that came from a capture is marked as such, and Review
  evidence distinguishes occurrences **you captured** from occurrences the detector found.
- **Your capture and the LLM's candidate merge.** After the next learning run, a capture for the same
  load reconciles with the LLM's candidate for that load — one entry, carrying your name — instead of
  a duplicate.
- **A confirm gate for thin previews.** A preview built from fewer than three clean captured runs can
  still be confirmed, but only with an explicit "confirm anyway"; the override is logged.

## Fixes and maintenance

- **Learned candidates now carry their fingerprint.** This closes a gap from 0.2.2 where a freshly
  learned candidate could be missing the fingerprint used for identity matching; candidates stored
  before the update get one when they are read.
- **Correct across the autumn clock change.** Capture day boundaries are computed by calendar date,
  so a capture that spans a DST fall-back no longer gets wrong hour/weekday features.
- **Gaps at the very edge of a window are refused.** A sampling gap straddling the start or end of a
  capture window is now caught, so a run built on held data is not mistaken for a clean capture.
- **The validation holdout ignores capture windows.** The holdout used to check accuracy drops any
  samples inside a capture window and reports how many; the replay behind that check is unaffected.

## Install

Same as 0.2.0 — install or upgrade through the Home Assistant Marketplace ("Add from link",
`https://github.com/hrabbach/ha-powerguesser`), then restart Home Assistant. This build installs over
0.2.0, 0.2.1 and 0.2.2; the upgrade needs no reconfiguration and touches no stored device data.

## Known limitations

Unchanged from 0.2.2: this is a **0.x release** (the hardware UAT is still open); **30 s meters are
the design baseline**; step detection needs an **effective interval of 45 s or less**; **program
devices cannot be merged** in v0.x; and some device classes legitimately read **not validated**.

Specific to this release:

- **Captures are reached through admin services in this build.** The dashboard entities, the capture
  screen in the options menu and the automation surfaces ship in the next release.
- A captured run is judged from the whole-house signal; a run that overlaps another load can be
  refused as **contaminated** rather than captured.
- A single capture is not an accuracy claim — it seeds a preview that still needs the normal confirm
  and learning steps.

## Accuracy

No accuracy figure is claimed here. Accuracy remains the README table, generated from the validation
report; classes without a passing validation read "not validated".
